3. Data Required for Process Mining

The event log should identify:

- Case ID: A validated identifier for the process instance.
- Activity: A consistent activity name, such as Appointment, Prescription Started, Lab Started, Imaging Started, or Pharmacy-related activity where applicable.
- Timestamp: A valid event date and time.
- Event ordering: Events sorted chronologically within each case.
- Optional attributes: Service identifiers or other relevant fields, subject to availability and validation.

The final case definition and activity-mapping rules still need to be confirmed with the team.

4. Data Quality Checks

Before analysis, validate:

1. Missing values in required event-log fields.
2. Timestamp parsing failures and invalid timestamps.
3. Event ordering within each case.
4. Repeated records and repeated activities.
5. Whether service-specific missing values are expected or indicate data issues.
6. Consistency of activity names and case identifiers.

Missing values in laboratory, imaging, or pharmacy fields should not automatically be treated as errors because those services may not apply to every appointment.
